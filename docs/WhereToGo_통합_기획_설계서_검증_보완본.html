1. 검증 요약

원본 설계서는 WhereToGo의 문제 정의, RAG + Agent 방향, Topic 중심 설계, 학습 계획/진행 데이터 분리 의사결정을 전반적으로 잘 설명한다. 다만 일부 항목은 초기 기획 또는 미래 확장안이 현재 구현 사실처럼 포함되어 있어, 최종 제출용 문서에서는 실제 코드 기준으로 수정해야 한다.

1.1 실제 구현과 일치하는 핵심 내용

영역검증 결과근거 코드
RAG + Agent 구조 입력 분석, 검색, 커리큘럼 생성으로 이어지는 LangGraph 기반 Agent 구조가 구현되어 있다. ai/agent/graph.py, ai/agent/nodes/

1.2 수정이 필요한 핵심 불일치

원본 설계서 표현실제 구현보완 방향
interview_sessions, interview_messages가 핵심 ERD에 포함됨 별도 Django interview 앱/모델/API는 구현되어 있지 않다. 프론트의 /chat 화면은 sessionStorage 기반 질문 흐름이다. 현재 구현 ERD에서는 제외하고, 향후 확장 항목으로 분리한다.
user_skill_profiles, learning_notes 포함 해당 모델은 존재하지 않는다. 미구현 확장 항목으로 명시한다.
/api/auth/logout/, /api/auth/me/ 실제 구현은 /api/users/me/, /api/users/me/profile/이다. logout API는 없다. API 표를 실제 URL 기준으로 수정한다.
/api/interviews/... API 백엔드 interview API는 구현되어 있지 않다. 현재 프론트 질문 흐름은 /chat, /interview/summary 화면으로 설명한다.
generation_id 초기화/상태 조회 API 실제 구현은 /api/curriculums/generate/stream/ 단일 스트리밍 응답이며 별도 generation 상태 테이블/API는 없다. “보완 설계/향후 개선”으로 이동한다.
/curriculums/:id 프론트 라우트 실제 Vue route는 단수형 /curriculum/:id이다. 화면 경로 표를 실제 router 기준으로 수정한다.

5. AI/RAG/Agent 구현 보완

원본 설계서의 RAG + Agent 방향은 실제 구현과 대체로 일치한다. 보완할 점은 “Topic Resolver”가 독립 API나 별도 저장 모델이라기보다 ai/agent/nodes/input_analysis와 topic_catalog_service를 통해 Agent 입력 분석 과정에 포함된다는 점이다.

구성실제 구현
Agent 실행ai.agent.run_agent(raw_input, catalog)가 ai/agent/graph.py의 graph를 실행
Topic catalogapps/curriculum/services/topic_catalog_service.py에서 활성 topic 후보 구성
검색ai/search/searcher.py가 ChromaDB courses/resources collection 조회
생성 promptai/agent/nodes/curriculum/01_prompt_builder.py
식별자 검증ai/agent/nodes/curriculum/03_validator.py에서 검색 결과에 없는 course/resource 제거
저장apps/curriculum/services/curriculum_save_service.py에서 FK 변환 및 transaction 처리

6. StreamingHttpResponse 구현 보완

원본 설계서의 Streaming 방향은 실제 구현과 일치한다. 다만 별도 generation_id 기반 상태 조회 API는 현재 구현되어 있지 않으므로, 현행 구현은 “단일 streaming 요청에서 progress/done/error를 전달하는 방식”으로 설명해야 한다. 

event: progress
data: {"message": "...", "progress": 45}

event: done
data: {"message": "...", "progress": 100, "status": "success", ...}
백엔드 단계progress설명
입력 검증10serializer 검증 및 raw_input 변환
Topic catalog 구성25AI Agent에 전달할 topic 후보 구성
Agent 실행45RAG 검색과 LLM 생성 수행
결과 정규화80프론트 preview 응답으로 변환
완료100최종 payload 반환

프론트엔드는 fetch와 ReadableStream으로 SSE chunk를 읽고, InterviewSummary.vue에서 progress bar와 문구를 갱신한다. 또한 progress interpolation을 적용해 45% 이후 AI 호출 구간에서 화면이 멈춰 보이는 문제를 완화했다.

8. 최종 보완 결론

WhereToGo의 실제 구현은 원본 설계서의 핵심 방향인 “Topic 기반 RAG + Agent 추천”, “학습 계획과 실행 상태 분리”, “Streaming 기반 생성 UX”를 충실히 반영한다. 다만 최종 제출 PDF에서는 초기 설계로 남은 면담/진단/상태조회 API를 현재 구현 범위와 분리해야 한다.

최종 문서에는 다음 원칙을 적용하는 것이 가장 정확하다.

  • 실제 Django 모델에 없는 ERD 테이블은 핵심 구현에서 제외하고 향후 확장으로 표기한다.
  • API 표는 config/urls.py, apps/accounts/urls.py 기준으로 다시 작성한다.
  • 프론트 화면 경로는 frontend/src/router/index.js 기준으로 교정한다.
  • 학습 대시보드 API와 데모 seed 데이터는 중요한 구현 사항으로 추가한다.
  • generation_id 상태 조회는 현재 구현이 아니라 향후 고도화 항목으로 둔다.
